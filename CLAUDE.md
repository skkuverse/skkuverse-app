# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository. It holds what an agent must know mid-session that the code, an ADR or a doc does not tell it where it needs it.

## Documentation

**Before writing or editing any document, read `docs/README.md`**, the SSOT for the writing rules: a doc holds only what the code cannot say, its frontmatter, kebab-case names, and pointing at the source of a value rather than copying it. `yarn lint:md`, chained into `yarn lint`, runs the umbrella's vendored `.markdownlint.jsonc`, which is edited upstream only. `docs/`, `README.md` and this file are English by fleet policy; Korean product copy carries a `conventions:allow-korean` marker on its line.

Skkuverse is the SKKU campus app, a **Yarn workspaces monorepo**: the Expo app in `apps/mobile/`, and `packages/shared`, `packages/sds` and `packages/bridge` (`README.md` has the layout). Every browser surface, the pages the app loads in a web view and the admin console, lives in [skkuverse-web](https://github.com/spencer0124/skkuverse-web) ([umbrella ADR 0005](https://github.com/spencer0124/skkuverse/blob/main/docs/decisions/0005-web-surfaces-dedicated-repo.md)).

## Common Commands

```bash
yarn install               # from the root
yarn typecheck             # tsc --noEmit across apps/mobile and every package
yarn lint                  # ESLint (--max-warnings 0), the disable guard, the suppressions ratchet, markdownlint
yarn test                  # every package's tests, apps/mobile (node:test) and the repo checks (scripts/*.test.mjs)
cd apps/mobile
yarn start                 # Metro on 127.0.0.1:8081 only, no Bonjour advert; start it first
yarn ios                   # build and run iOS against that Metro (--no-bundler)
yarn android               # build and run Android against that Metro (--no-bundler; adb-reverses 8081)
yarn start:lan             # opt-in: Metro on every interface, for an iPhone over Wi-Fi only
npx expo prebuild --clean  # after a native change, then yarn ios or yarn android
```

- Node is pinned to 22 in `.nvmrc`, which `--experimental-strip-types` requires. Expo Go is not used: the custom native modules make every run a native build (CNG).
- **CI runs on `main` only** (`.github/workflows/ci.yml`, jobs `conventions`, `workspace` and `prose`): a pull request to `main` and a push to `main` run every job, a newer push to a pull request cancels the run it supersedes, and a `main` run is never cancelled. `dev` has no CI, so run `yarn typecheck`, `yarn lint` and `yarn test` locally before pushing there (the local commit gate runs the light checks). **A new workflow file needs a `!` line in `.gitignore`**, which makes `.github/` an allowlist; without it the file is untracked and never runs, with no error.

## Architecture

- **Read [ADR 0020](docs/decisions/0020-app-architecture.md) before adding a file under `apps/mobile/src/`.** It sets the module shape: MVVM with hook ViewModels plus Repository, flat feature folders whose root is their public surface, and a closed file-name vocabulary. The `arch/*` lint rules and the `scripts/architecture/` tests are the source of truth, not this file. Copy `apps/mobile/src/features/home/`. **Feature modules** (`src/features/`): one folder per feature, in the shape ADR 0020 sets (role files flat, `components/` the only subfolder, its root the public door).
- **Read [`docs/reference/code-shape.md`](docs/reference/code-shape.md) before writing or refactoring code.** It holds the code-shape rules that lint cannot check (types, placement, reuse, platform APIs), each under an ID that review cites.
- **Comments: the code says what; a comment says only what the code cannot** ([ADR 0026](docs/decisions/0026-comments-say-only-what-the-code-cannot.md)). Default to none. A comment, JSDoc included, opens with `QUIRK(<system>):`, `CONTRACT(<repo>):` citing `<repo>/<path>` in a public repo, `EVIDENCE:`, `WHY:` or `SEE: docs/<path>`; runs at most three lines; never says what the code does or its history; names no feature in a shared layer (`packages/*/src`, `src/platform`, `src/components`); and is English. `yarn test` and the commit gate fail on any violation, with no allowlist; `node scripts/architecture/comments.mjs --report [path...]` lists them.
- **Two navigation shells, one override ([ADR 0023](docs/decisions/0023-custom-tab-bar-with-glass-on-ios-26.md)).** `app/(tabs)/_layout.tsx` mounts `SharedMapShell` on every build, or `NativeTabsShell` only when the local `SHELL_OVERRIDE` in `apps/mobile/src/bootstrap/shell.service.ts` says `'native-tabs'`; never commit a forced value. Only route files (and `useTabFocusTracking`) read `SHELL`, branching at module scope; a feature never does, and gets shell differences as data (view tables, `tabScope`). What a store build leaves out is one list, `PRERELEASE_GATES` (`apps/mobile/src/platform/ota.rules.ts`), read at each site as `isGateOpen('<gate>')`; a closed gate means absent, never a fallback. Detail: `docs/explanation/shared-map.md`.
- While the native-tabs shell exists, a tab screen's root is directly a ScrollView, SectionList or FlatList, with loading and error states swapped inside it: `docs/explanation/ios-26-native-tabs-minimize.md`.
- Every modal route re-mounts its own `<SafeAreaProvider>`, since the root one measures another view controller's insets (the `QUIRK` in `app/profile-setup.tsx`).
- A header takes `useDefaultHeaderOptions()`, and its right-hand icon is `HeaderIconButton` (both in `apps/mobile/src/components/`), whose `QUIRK` says why a bare icon stretches on iOS.
- `router.d.ts` under `apps/mobile/.expo/types/` is generated by the Metro dev server and gitignored, so code must compile without it, as a clean checkout and CI do.
- **Retries live in one place.** axios-retry (`packages/shared/src/api/interceptors/retry.ts`) is the only retry layer, and React Query's `retry` is off (`packages/shared/src/store/query-client.ts`); never add a per-query `retry`, since the layers multiply into a synchronized burst. 429 is never retried. Timeouts live in `packages/shared/src/api/timeouts.ts`, and a retry starts a fresh one.
- **A query with a fallback throws, and the hook applies it** with `dataOrFallback(query, DEFAULTS)` (`packages/shared/src/store/fallback.ts`), as `useMapConfig` does. Defaults returned from a `queryFn` cache the failure as a success for the whole staleTime.
- **staleTime never exceeds the server's `max-age`.** `Cache-Control` is the freshness knob; a longer staleTime holds data the server has already corrected.
- **Stores:** `useAuthStore` and `useSettingsStore` in `packages/shared/src/store/`, `useMapStore` in `apps/mobile/src/features/map/map.store.ts`.
- **User data lives in Firebase** (Auth and Firestore, which the client reads and writes directly), and public data comes through the backend API ([ADR 0005](docs/decisions/0005-user-firebase-public-mongodb.md)); device-local state is MMKV.
- **Web surfaces:** what crosses into skkuverse-web is `packages/bridge`, the message contract, vendored there and hash-checked by the umbrella's contract registry, so change it here and never the copy; and the token values in `packages/shared/src/tokens/`. The origin allowlist that grants web pages the native bridge is **server-owned** (skkuverse-server `src/infra/origins.ts`, served by `GET /app/config`), so a new host grants nothing until the server ships it.

### Notices Feature (`src/features/notices/`)

- **The gate:** the tab shows `OnboardingLanding` while `isAnonymous || !onboardingCompleted` (`showsOnboardingLanding`, `apps/mobile/src/features/notices/notices.rules.ts`); an account has to be on `@g.skku.edu`.
- **Keep the restore dual write.** The sign-in handler in `features/notices/useNoticesTab.ts` and `restoreOnboardingFromPreferences` (`features/notices/notices.service.ts`, run by `useAppInit.ts`) both write the same data; never change one alone.
- **`onboardedAt` is null until onboarding completes.** The complete gate is committed only after the Firestore write succeeds, or a user is marked onboarded with no `preferences/main` and every picker save fails.
- **The `'dept'` key is a literal in many places**, in the app and in the server-side functions kept outside this repository. Rename it only as a coordinated change, finding every site with `grep -rn "'dept'\|\.dept\b"`. Adding a tab: `docs/how-to/add-notice-tab.md`.
- **The gate branch unmounts the header and the bottom accessory** (`headerShown: false`, the accessory prop `undefined`); hiding or covering them does not work.
- **The first-launch intro is not the notices wizard.** The tour (`src/features/tour/`) is a branch of `apps/mobile/src/bootstrap/InitGate.tsx`, not a route, shown once to anyone not signed in with Google; `seen.intro` never unlocks the notices tab, and the wizard's `skipLogin` is frozen at mount, never recomputed from the live `isAnonymous`. Their reasons are comments in `InitGate.tsx` and `features/notices/onboarding/useOnboarding.ts`.

### In-app games (`src/features/games/`)

- **Adding a game, the release order across repos and the hosted page's trust: `docs/explanation/in-app-games.md`; the decision is ADR 0021, which superseded ADR 0009.** A game is a skkuverse-mini static site on its own `<id>.game.skkuverse.com` origin, hosted by the screen at `/games/[id]`.
- **`GET /games` decides which page opens** (`features/games/games.client.ts`, `exposure.rules.ts`): only a hosted id with a `FIRST_PARTY_GAMES` entry opens, and nothing falls back to a web mini app. Games and mini apps share one id namespace, and games resolve first.
- **A hosted page gets the `game.*` notifications alone** (`GAME_GRANTS`, `features/games/host/page.rules.ts`), decided per message from the posting origin against `games.origins`, never `webview.bridgeOrigins`, with its navigation pinned to that origin. It speaks `@skkuverse/miniapp` through `bootGame`, never `packages/bridge`, asks for no device capability and exposes no engine debug option.
- **Scores go through callables:** `startRun` when a run starts, then `submitScore` with the result and the validator version the page names, and the rank comes from the answer. A scoring change is a new validator version; the callables and the version ship before the page or OTA that uses them.
- **The app only reads runs and board entries** (`users/{uid}/gameRuns`, `leaderboards/{gameId}/scores`) and of the game data writes only `users/{uid}.profile`, with `updatedAt: serverTimestamp()`. A sign-in that changes the uid calls `claimRun` with the anonymous ID token, and no submit decision is made while it is in flight.
- **A score's direction is per game:** `score.order` (`features/games/registry.rules.ts`) drives every comparison through `isBetter` (`features/games/leaderboard.rules.ts`). Never compare two scores with a bare `>`; a change to `score.order` is a cross-repo change. Players only ever see "Hall of Fame" (명예의 전당), never "leaderboard". <!-- conventions:allow-korean: the product term -->

### Design System (`@skkuverse/sds`)

UI code builds from SDS components first and reads colors as roles only. The token values live in `@skkuverse/shared/tokens/` and nowhere else.

- **When to use what:** [`docs/reference/design-usage.md`](docs/reference/design-usage.md), every usage rule under the ID the `sds/*` lint messages cite. The words on screen: [`docs/reference/ux-writing.md`](docs/reference/ux-writing.md).
- **How a component or token works:** [`packages/sds/SDS.md`](packages/sds/SDS.md), including its "Lint rules" table. The decisions are ADRs 0011 to 0019 in `docs/decisions/`.
- **Colors are roles** through `useSemanticColors()` or `createThemedStyles()`, never a value or a module-scope read. Type, spacing and radius come from their scales, and a press is SDS `Pressable` with a `bg` role.
- **Content in a glass sheet paints no layer fill.** `Sheet` provides a surface context to its content and footer (`useSurface()`: `glass` inside `surface="glass"`, `opaque` elsewhere). The sheet draws the layer itself, so `Pressable` resolves a `layerDefault` or `layerFloating` `bg` to transparent there, and a hand-painted panel reads `useSurface()` and drops its fill too; a second layer fill shows as an opaque white block on iOS 26 glass. Other roles are kept. Detail: `packages/sds/SDS.md`, design-usage COLOR-12.
- **Lint is the gate, and the record only shrinks.** The `sds/*` rules run at error over `eslint-suppressions.json`: fix the code, `yarn lint:prune`, never `--suppress-*` ([ADR 0016](docs/decisions/0016-ratchet-lint-debt-with-bulk-suppressions.md), [`docs/how-to/work-under-the-lint-ratchet.md`](docs/how-to/work-under-the-lint-ratchet.md)).
- **For agents:** reading or editing UI code loads `.claude/rules/sds-ui.md`, and the `sds` skill holds the procedures.

## Key Technical Details

- **Deep links:** `skkuverse://` and `https://skkuverse.com/p/...` pass one whitelist, `apps/mobile/src/bootstrap/deep-links/deep-links.rules.ts`, routed by `deep-links.service.ts` beside it. Only a path with a web landing page gets `/p/` and an AASA entry; every other allowed path is custom scheme only, by design (`docs/reference/deep-link.md`). The filter is identical on cold and warm starts, so an untrusted link cannot push an internal route such as `/login`; only bare `/` differs.
- **One map under two tabs ([ADR 0022](docs/decisions/0022-places-open-on-the-map-intents-start-in-transit.md)).** A tab's task is a sheet stack in `useMapStore.tasks[tab]`, written only through `dispatchTask` → `reduceMapTask` (`apps/mobile/src/features/map/map-task.rules.ts`). Transit imports map, and map names transit only through `import type`, or `scripts/architecture/feature-cycles.test.mjs` fails on the cycle.
- **An overlay's `kind` is an open enum:** an unknown one drops that overlay alone (`OVERLAY_KINDS` in `overlay.schema.ts`), never through an exhaustive `never` that would blank a layer on an old build.
- **`[lng, lat]` becomes `{lat, lng}` once, in `toLatLng`** (`apps/mobile/src/features/map/geometry.rules.ts`), because an axis swap never throws.
- **Polygon rings are reversed unconditionally** (`apps/mobile/src/features/map/components/canvas/overlay-geometry.rules.ts`); a wrongly wound ring draws but refuses taps, so verify by pressing the zone.
- **A layer's visibility is five tiers, each a fallback, never an assignment** (`locked ?? stackLens ?? userToggle ?? tabDefault ?? defaultVisibleAt(layer, now)`); `useMapStore` holds only what the user expressed.
- **A non-null `chipGroupId` marks festival content** (`isFestivalLayer`, `apps/mobile/src/features/map/layers.rules.ts`), and the server alone decides when a festival shows; the app has no festival switch.
- **The campus toggle never moves on its own** ([ADR 0008](docs/decisions/0008-campus-camera-reconciliation.md)): only the user changes it, and a card offers the camera's campus instead (`apps/mobile/src/features/map/camera-request.rules.ts`).
- **No map marker has React children**, only an image, a tint and a native caption: on Android the library redraws a child-View marker into a bitmap every 40 ms (`apps/mobile/src/features/map/components/canvas/MapOverlayLayer.tsx`).
- **`pointerEvents` goes on a wrapping `View`, never a third-party native component:** on Android it reaches only a `ReactViewManager`, so a `ViewGroupManager` such as `SafeAreaListener` drops it silently and a full-screen one takes every touch while iOS works (the `QUIRK` in `apps/mobile/src/features/map/MapHost.tsx`).
- **Analytics events go through `track()` (`apps/mobile/src/platform/analytics.ts`) and `EventMap` (`analytics.types.ts` beside it)**, never an ad-hoc `logEvent`. A sheet, modal or hosted page logs with `useViewTracking`, never a `screen_view`, and an action inside it with `item_action`; extend the `ViewName`/`ItemAction`/`EntrySource` unions before inventing an event. Log ids, never emails, nicknames or location. An app-made tab switch calls `markTabSwitch(tab, cause)` just before it navigates; `map_chip`'s `tab` and `ran_in` come from the shared-map shell alone. A game's `telemetry` goes to analytics only. Detail: `docs/explanation/analytics.md`.
- **The cold-start anonymous sign-in never blocks launch.** `anonymousSession.ensure()` (`apps/mobile/src/features/auth/auth.service.ts`, scheduled by `anon-session.rules.ts`) tries once, lets launch go on signed out, and retries in the background. **Nothing else calls `signInAnonymously`**; an attempt re-checks `currentUser` right before calling and after its App Check probe, because the call replaces a signed-in Google user; and every Google sign-in path `pause()`s the session first and `resume()`s after (pauses nest), as `signInWithDeviceMigration` does.
- **Push notifications (FCM)** are option D: no inbox, a locally computed badge ([ADR 0002](docs/decisions/0002-no-notification-inbox.md)). **The architecture is `docs/explanation/fcm-architecture.md`** (the intent it writes, the write rules, display and taps, auth transitions). The client writes intent alone, each write a single dot-path `updateDoc` with **no transaction**, which keeps offline queueing; MMKV holds device-local state alone, and a Firestore listener is the single source for preferences.
- **The FCM auth transition invariant:** a new sign-in path mirrors `signInWithDeviceMigration` (`features/auth/auth.service.ts`): `unregisterDevice` first, then sign in, then `await initializeFirestoreNotifications`.
- **App Check:** debug token injection (only the env path works on the simulator), the strip from every build and OTA publish (default-deny on `EAS_BUILD_PROFILE` and `RELEASE_CHANNEL`) and Play Integrity throttling are in `docs/explanation/app-check.md`. When a token exchange fails on the simulator, check the console's debug token registration first.
- **Metro listens on loopback only**, since a LAN-reachable Metro serves its bundle to anyone on the network. `yarn start` is `--localhost` with Bonjour off and `--dns-result-order=ipv4first` (an Android emulator reaches the host over IPv4 `10.0.2.2`), and the run scripts pass `--no-bundler`, since `expo run:*`'s own bundler binds every interface. After replugging a USB Android device, rerun `adb reverse tcp:8081 tcp:8081`. Stop a `yarn start:lan` Metro when the session ends.
- **`@mj-studio/react-native-naver-map` is pinned exact, with no patch:** a caret would pull a native SDK bump that needs a prebuild and a native rebuild. Never go below 2.8.0, which moved the iOS image loader off `RCTImageLoader` (the crash cluster in spencer0124/skkuverse#53).
- **`@gorhom/bottom-sheet` is pinned exact and patched.** Raise it only once upstream fixes #2669 and the `switch` stack; drop the scroll-lock hunk once #2737 ships: `docs/explanation/bottom-sheet-system.md` ("The gorhom pin and its patch").
- **`react-native-webview` and `react-native-screens` are pinned exact, each with a native patch.** Webview carries the `@synchronized` fix of react-native-webview#3916, since the release that ships it types `<WebView>` props as `never` (#3970); drop it when webview moves past 13.x. Screens carries a backport of software-mansion/react-native-screens#4413, an Android launch-time use-after-free; drop it at screens 4.28.
- **`react-native-keyboard-controller` is pinned exact and in `expo.install.exclude`:** the version Expo expects lacks two crash fixes on the provider path, and `expo install --fix` would take it back down. Drop the exclude once the SDK's expected version has them. It mounts on iOS only (the `QUIRK` in `apps/mobile/src/bootstrap/KeyboardProvider.tsx`).
- **`@react-native-firebase/*` moves as one exact version**, and `apps/mobile/plugins/withFirebaseModularHeaders.js` pins the iOS SDK under it (its header says when to drop that). The pin holds only with `ios.disableSPM` in `app.config.ts`, and this CocoaPods path ends at Firebase 12.x, so revisit it with the SDK 58 move. Call the modular API; the namespaced one is gone.
- **A library that holds React context or global state is installed once** (`scripts/check-singletons.mjs`, in CI and before every OTA build); when it fails, align the ranges so yarn hoists one copy.
- **Every patch in `patches/` must be in effect** (`scripts/check-patches.mjs`, `--fix` re-applies): yarn v1 skips the root `postinstall` on a `yarn add` or `yarn remove` inside a workspace and on a root `yarn remove`. A patch file is named for its package's version in `apps/mobile/package.json`, so a bump regenerates or drops it in the same change.
- **`useLegacyPackaging: true` in `app.config.ts` stays:** without it an x86_64 emulator with ARM translation crashes on launch.

## Build (local builds)

Release builds are made locally with **EAS Build `--local`**, never in the EAS cloud; the maintainers run store releases and OTA updates from outside this repository. The procedures: `docs/how-to/ios-build-deploy.md` and `docs/how-to/android-build-deploy.md`; how the app takes an update: `docs/explanation/ota-updates.md`.

- The Firebase client configs and `.env` are gitignored. `.easignore` applies in place of `.gitignore`, so the Firebase config and `keys/hot-updater-public.pem` have to stay included in a build archive, and **`.env` is deliberately excluded from it**.
- **The API host is a committed constant, and on a shipping profile the environment cannot influence it.** `PROD_API_URL` lives in `apps/mobile/config/constants.js`; `resolveBaseUrl()` in `apps/mobile/app.config.ts` does not read `EXPO_PUBLIC_BASE_URL` at all whenever `EAS_BUILD_PROFILE` or `RELEASE_CHANNEL` names `beta` or `production`. Off a shipping profile the variable is an optional local override.
- **Two settings a local EAS build needs in this monorepo. Without both, the embed bundle step fails with `Unable to resolve module .../apps/mobile/index.ts` and `ARCHIVE FAILED`:** (1) **`EXPO_NO_METRO_WORKSPACE_ROOT=1`** in the beta and production env in `eas.json`, because a recent @expo/cli turned the Metro workspace-root on by default, and in the EAS sandbox (which creates a nested `apps/mobile/node_modules`) the server root becomes the monorepo root, which breaks the `tsconfig` `@/` paths. The flag also switches off autolinking module resolution, so a nested duplicate of a native module would reach release binaries alone; **never remove `experiments.autolinkingModuleResolution: true` from `app.config.ts`**, which keeps it on. (2) **a `TMPDIR` with no symlink in its path** (`export TMPDIR="$HOME/.eas-build-tmp"`), because `/tmp` and `/var/folders` are symlinks to `/private/...`, leaving the entry (symlinked) and Metro's server root (realpath) mismatched. **This failure does not reproduce in the local repo**, which is fully hoisted; debug it by running `expo export:embed` directly inside a live EAS sandbox during a build. Do not repeat full builds. Detail in `docs/how-to/ios-build-deploy.md`.
- Updates target the app `version` in `apps/mobile/app.config.ts`, so it must equal the store build's. A change that cannot travel over the air (a native module, an SDK upgrade, an `app.config.ts` plugin, a signing key) needs a native rebuild and a `version` bump (`docs/explanation/ota-updates.md`).
